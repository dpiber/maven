# M4L4 / Krok 3 — decyzja w wywiadzie planera (`/10x-plan`)

Repo: https://github.com/apache/maven (Java)  
Zmiana: `context/changes/refactor-opportunities/`  
Wejście: zweryfikowany `research.md` (krok 1–2) + Twoje notatki z lektury (kolejność, spory z rankingiem, `unknown`)

## Wymagania konieczne

- Ranking z researchu to **propozycja**, nie decyzja — pierwsze pytanie wywiadu ma dotyczyć **wyboru opcji**.
- Wąski zakres: jedna opcja (+ ewentualny tani, szybki zysk, np. guard/test) i jawne „czego NIE robimy”.
- Zero implementacji w tym kroku — tylko wywiad + `plan.md`.
- Stack: decyzje wokół ModelBuilder / ProjectBuilder / twin M3↔M4 / unit+ITS — nie PostStore / searchlayer z lekcji.

```text
Pracujemy w apache/maven (Java). Zmiana: refactor-opportunities.
Prior Deep Focus i dług: context/changes/model-builder-flow-analysis/research.md
(raport opcji: context/changes/refactor-opportunities/research.md — przeczytany i zweryfikowany ast-grep).

/10x-plan refactor-opportunities

Planer ma czytać research.md z folderu zmiany i nie pytać diagnostycznie o stan kodu —
pytania poświęć decyzjom projektowym.

Czego pilnuję w wywiadzie (odpowiadam ja, człowiek):

1. Pierwsze pytanie = wybór opcji (akceptacja / przesunięcie / odrzucenie pozycji rankingu).
   To moja decyzja, nie „potwierdź ranking”.
2. Przetestuj przynajmniej jedną ⭐ rekomendację kontrpytaniem, nawet jeśli wygląda dobrze
   (np. „czy to nie świadome ograniczenie / personality M3?”, „czy guard wystarczy zamiast split hubu?”).
3. Utrzymuj wąski zakres: jedna opcja (+ ewentualny tani szybki zysk z odrzuconych /
   z wejść wykonalności, np. brakujący unit na ścieżce error) i jawna sekcja „czego NIE robimy”.
4. Jeśli w raporcie zostały unknown (Jacoco %, wiring ClassRealm/SPI, paired twin) —
   wnieś je świadomie do planu albo zapisz jako follow-up, nie odkrywaj w połowie implementacji.
5. Preferuj porządek guard-first / charakteryzacja przed edycją; Strangler / Branch by Abstraction
   tylko gdy wybrany kandydat to migracja struktury, nie sam guard.

Po wywiadzie oczekuję plan.md w context/changes/refactor-opportunities/ z fazami
ułożonymi od najtańszej i najbardziej samodzielnej, z kryteriami weryfikacji.
Nie uruchamiaj jeszcze /10x-implement ani /10x-plan-review — to krok 4.
```
