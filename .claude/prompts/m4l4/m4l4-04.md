# M4L4 / Krok 4 — odbierz plan, sprawdź właściwości, `/10x-plan-review`

Repo: https://github.com/apache/maven (Java)  
Artefakt: `context/changes/refactor-opportunities/plan.md`  
Cel ćwiczenia M4L4: element ④ + plan jednej bezpiecznej zmiany — **kończysz na planie**; fazy implementujesz później.

## Wymagania konieczne

- Najpierw własny przegląd `plan.md` (checklista poniżej), potem `/10x-plan-review` w **nowej** sesji.
- Nie startuj `/10x-implement`, dopóki review nie przejdzie — albo świadomie odłóż implementację (lekcja zatrzymuje się na planie).
- Testy w planie = JUnit w module + ewentualnie ITS (`its/core-it-suite`), nie storetest z Mattermosta.
- Mechanizm vs egzekwowanie: jeśli plan dodaje guard/walidację — testy przechodzą najpierw; włączenie egzekwowania = osobna, jawna faza.

### Checklista właściwości planu (przed review)

1. **Charakteryzacja przed dotknięciem** — tam, gdzie plan edytuje kod bez pokrycia, najpierw test utrwalający obecne zachowanie (np. parent mismatch FATAL / `maven3Personality` → WARNING, call-site ProjectBuilder→ModelBuilder).
2. **Fazy = odwracalne commity** — od najtańszej i najbardziej samodzielnej fazy; każdą da się cofnąć osobno.
3. **Kryteria weryfikacji** — każda faza: automatyczne (Surefire/Failsafe / wybrany IT) + ręczne.
4. **Mechanizm z zielonymi testami, egzekwowanie osobno** — jeśli dotyczy (guard / flaga / lista wyjątków).
5. **Jawne „czego NIE robimy”** — bez rozlewania na cały hub DefaultModelBuilder / cały most M3↔M4 / mvnup / Dependabot.
