# M4L3 / Krok 0 — wybierz cel Deep Focus z mapy

Repo: https://github.com/apache/maven (Java / multi-module Maven 4)  
Kontekst: lekcja Mattermost/Go (`PostStore.Save`) — u nas ten sam proces, inny stack i inny feature.  
Artefakt wejściowy: `../../../context/map/repo-map.md` (Wide Scan z M4L2).

## Wymagania konieczne

- Nie refakturuj, nie zmieniaj kodu, nie uruchamiaj jeszcze `/10x-research`.
- Nie czytaj całego repo — pracuj wyłącznie na `../../../context/map/repo-map.md` (ew. sprawdź istnienie ścieżek z sekcji „Pierwszy dzień”).
- Wybierz **jeden** przepływ / feature, nie cały podsystem (np. nie „całe maven-core”).

```text
Otwórz context/map/repo-map.md (apache/maven) i wybierz JEDEN przepływ do Deep Focus.

Decyzję oprzyj wyłącznie na trzech sekcjach mapy:

1. Strefy ryzyka — stąd cel (czuły / nośny / twardy coupling).
2. Pierwszy dzień — stąd 2–3 entry pointy (pliki Java, nie katalogi).
3. Ograniczenia — stąd pierwsze unknowns do potwierdzenia lub obalenia.

Rekomendacja z mapy (możesz ją przyjąć albo uzasadnić inny wybór z tej samej mapy):
- Strefa 1: budowanie modelu POM (profile, parent, CI-friendly ${revision}).
- Entry pointy: DefaultModelBuilder (impl), DefaultProjectBuilder (core), legacy twin DefaultModelBuilder (compat/maven-model-builder).
- Unknowns z mapy: DI / ClassRealm / refleksja / SPI poza jdeps; drift mostu M3↔M4; wpływ ekosystemu pluginów poza reactor.

Stack (różnica vs lekcja Mattermost/Go):
- Język: Java (nie Go). Warstwy: api ← impl ← core ← cli + compat (nie PostStore/SQL).
- „Zapis” w sensie lekcji = budowa / materializacja modelu POM i przejście model → project, nie zapis do DB.
- Testy: unit w module + its/core-it-suite (lustro regresji), nie storetest.
- Generowane: .mdo / codegen — tańsze sprzężenie niż ręczna edycja obu światów.

Sformułuj wynik w dokładnie tym formacie (1–2 akapity + lista):

## Cel Deep Focus
Jedno zdanie: co badam, od którego pliku zaczynam, dlaczego mapa wskazała ten obszar.

## change-id
Krótki kebab-case (np. model-builder-flow-analysis) — pójdzie do /10x-new i ścieżki context/changes/{change-id}/.

## Entry pointy (2–3)
Ścieżki plików z „Pierwszy dzień” / strefy ryzyka.

## Pierwsze unknowns
3–5 punktów z sekcji Ograniczenia + strefy, które research ma potwierdzić lub obalić.

## Co NIE wchodzi w zakres
1–3 sąsiednie obszary z mapy, których świadomie nie ruszamy (np. mvnup, całe ITS jako źródło prawdy, Dependabot).

Nie generuj jeszcze research.md. Nie uruchamiaj skilli 10x poza ewentualnym odczytem mapy.

Wynik zapisz do .claude/prompts/m4l3/m4l3-00-out.md
```
